# Cyclo 1.5.0 Release Preparation

Date: 2026-11-11 (Asia/Seoul). This is release preparation, not a statement that
the 1.5.0 image or a release tag has already been published.

## Changes

- Central Policy Runtime owns control, buffering, robot publication, and pose
  safety; manifest-discovered Workers own model computation.
- ABot-M0, LingBot-VLA, and RLDX integrations join LeRobot and native GR00T.
- Action Steps selects how many original model waypoints are consumed; runtime
  status reports the observed chunk size independently of the selected limit.
- Saved initial poses support configurable Return and Stop, separately from
  model Clear. Slow Start remains a distinct inference option.
- Inference recording supports Record/Save/Discard and explicit folder reuse.
  Try Results remains separate and writes the selected model's evaluation JSON.
- Graceful recording shutdown requests native recorder STOP before closing ROS
  and preserves unfinished data without automatic Save/Discard.
- Main's Autonomy Studio and navigation changes are retained alongside Runtime
  lifecycle, cancellation, and Worker maintenance guards.
- Main through `11800ba49ff2f52342ba520138759a9e8bf56153` is integrated,
  including the 1.4.5 episode-number fixes and Discord release notifications.
  Published changelog entries are retained below the new 1.5.0 sections.
- Episode deletion uses the recording/shutdown command lock. All task deletion
  is rejected during live recording or archiving, so deleting another task
  cannot delay recording STOP. Retry after recording and archiving finish.
- Queued/running video conversion prevents deletion or renumbering of its task,
  even when that task is not selected. Completed conversion allows editing.
- Refreshing episode numbers preserves the inference recorder's rule against
  resuming interrupted episodes; their on-disk data remains reserved.
- Supervisor CI installs the TestClient-only `httpx` dependency explicitly.
  Production dependency requirements are unchanged.

## Images and Release Ownership

Cyclo core remains a published image. All model Workers, including LeRobot and
GR00T, are built locally from Cyclo's checkout and pinned upstream submodules.
The Compose Worker image names are local build tags; no Worker pull fallback is
used. Existing registry images are not deleted by this change.

The core Compose tag is `robotis/cyclo-intelligence:1.5.0`. Current repository
automation publishes through the main-to-jazzy release flow, or the manual
Docker publish workflow for an existing release. Opening or merging the main PR
alone does not publish an image. Do not use the new default tag until published,
unless explicitly building core from source with `start --build`.

Worker model support remains architecture-specific. Source builds do not imply
that every policy supports ARM64 or every JetPack/GPU combination.

## Upgrade from 1.4.x

1. Stop/Clear inference, finish or discard active recording, and stop pose
   return and navigation. Do not switch a source-mounted checkout during use.
2. Preserve deployment-specific Compose overrides, Zenoh `.bashrc` settings,
   model/data/evaluation folders, the old checkout commit, and old image IDs.
   Container recreation discards settings stored only inside the container.
3. Update the checkout and run `git submodule update --init --recursive`.
4. Recreate core using the published matching release, or explicitly build it
   with `./docker/container.sh start --build` before publication. Rebuild ROS
   interfaces and restart all consumers together. New `TaskInfo`, inference,
   Engine and pose definitions are not a supported mix with old services.
5. Rebuild each Worker that will be used, for example
   `./docker/container.sh start-lerobot --build`. This builds and starts the
   Worker, but does not request model inference. `build-policy lerobot` is the
   build-only alternative. Do not reuse an old tag without checking compatibility.
6. Restore the verified network settings and check Preview/camera/joint mapping
   before enabling physical command publication.

For rollback, stop work first and restore both the old source checkout and its
matching images. Restoring only an image is insufficient with source bind mounts.
Restore data from backups if a newer format is not readable by the old release.

## Open Validation and Known Issues

- Inference Start/Pause/Clear toolbar clipping at desktop panel widths and
  narrow-screen Action/Mission overflow are known and not fixed in this PR.
- ARM TorchCodec 0.11.1 fails to load with the retained Jetson Torch 2.7.0/CUDA
  12.8 stack (`libnvrtc.so.13` missing). ACT compute passed without that decoder;
  video dataset decoding is not validated. Removing `cuda/compat` does not fix it.
- Same-image JetPack 7 compatibility, physical Start/Stop/Pause/Return, real
  Deploy-mode Record/Save/Discard/Clear, and physical Nav2 remain to be validated.
- Native GR00T offline compute passed only with complete pinned Cosmos assets
  and an explicit local path alias. Unmodified offline loading is not a pass.
- Clean-machine installation, complete upgrade/rollback, long-duration camera
  stress, and full native-model training were not rerun for this integration.

Keep the PR in draft while resolving merge-blocking items or explicitly agreeing
on a narrower support scope. Do not describe these known gaps as completed tests.
