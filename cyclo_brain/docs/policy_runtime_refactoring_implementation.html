Cyclo Brain Policy Runtime
구조 변경 상세 보고서

현재 작업 트리에 구현된 코드를 기준으로 이전 구조와 달라진 점, 각 모듈의 책임, inference 데이터 흐름, 배포 효과, 검증 결과와 남은 위험을 설명합니다.

핵심 결론

기존에는 LeRobot과 GR00T 컨테이너가 각각 모델 추론뿐 아니라 action buffer, 제어 주기, 로봇 command 발행과 안전 정지까지 소유했습니다. 지금은 공통 제어 계층을 Cyclo 컨테이너의 중앙 Policy Runtime으로 옮기고 모델 컨테이너는 Engine-only Worker로 줄였습니다.

Centralized제어 계층 1개

session, ControlLoop, action chunk 처리, initial pose sync, 안전 정지를 Cyclo가 한 번만 구현합니다.

Isolated모델 Worker 분리

LeRobot과 GR00T는 framework dependency, 모델 load, 관측 전처리와 추론만 담당합니다.

정책 목록, capability와 UI parameter를 manifest에 선언하고 UI와 Supervisor가 같은 catalog를 사용합니다.

데이터는 어디로 움직이는가

제어 요청, observation, action chunk와 robot command는 서로 다른 경로를 사용합니다.

Control request

UI에서 모델 실행까지

UI → Orchestrator → Policy Runtime → Worker입니다. 작은 lifecycle request와 action chunk만 service를 통과합니다.

Observation

Robot에서 모델까지

Robot topic → Worker RobotClient → preprocessing입니다. Cyclo를 경유하지 않습니다.

Command

모델 결과에서 로봇까지

Worker action chunk → Runtime buffer/보간 → Cyclo RobotClient → command topic입니다.

main_runtime 이름이 남은 이유

디렉터리명은 기존 공통 runtime을 재사용해 남았지만 실행 위치는 Worker가 아니라 Cyclo입니다. 실제 s6 service 이름은 policy-runtime이며 기능상 중복 runtime은 아닙니다.

삭제된 Worker service

LeRobot과 GR00T에서 main-runtime s6 definition이 제거됐습니다. Worker healthcheck도 engine-process와 ready marker를 검사합니다.

Policy Catalog와 동적 UI

모델 실행 코드는 Worker에 있지만 어떤 모델을 보여주고 어떤 parameter를 받을지는 Cyclo manifest에서 결정합니다.

1manifestruntime, policy, capability, parameter 선언
2Loader형식, 중복 ID, Compose와 범위 검증
3Supervisor/api/policies/catalog 제공
4React UIselector와 field 생성
5RuntimeJSON canonicalize와 schema 검증

전역 ID

lerobot:act, groot:n17

콜론 앞은 runtime, 뒤는 model입니다. manifest의 model alias는 예전 bare ID를 읽기 위한 호환 기능입니다.

Parameter schema

모델별 UI를 선언으로 생성

text/path/number/integer/select/toggle, default, 범위와 visible_when을 지원합니다. GR00T TensorRT가 실제 예입니다.

models:
  - id: n17
    label: N1.7
    requires_instruction: true
    parameters:
      - key: acceleration_mode
        control: select
        binding: task_info.accelerationMode
        default: pytorch
        options: [pytorch, tensorrt_dit]
      - key: acceleration_engine_path
        control: path
        binding: task_info.accelerationEnginePath
        visible_when: {acceleration_mode: tensorrt_dit}
Policy alias의 범위: manifest의 aliases: [act]는 예전 policy 이름을 해석하기 위한 호환 정보입니다. Robot config에는 별도의 camera alias 계층을 두지 않으며, checkpoint key와 camera 이름의 일반적인 prefix 및 side/part 표기 차이만 shared resolver가 정규화합니다.

객관적 개선점과 남은 위험

구조가 새로워졌다는 사실 자체가 개선은 아닙니다. 중복, 배포, 통신, 장애 격리와 운영 복잡도를 나누어 평가했습니다.

개선

공통 제어 중복 제거

ControlLoop와 safety가 Worker마다 복제되지 않아 모델 수가 늘수록 효과가 커집니다.

개선

command ownership 단일화

한 global session과 한 Runtime이 command를 발행해 backend 간 제어 경합을 한 곳에서 차단합니다.

개선

모델 추가 시 UI 수정 감소

정책 표시, instruction과 parameter를 manifest로 옮겨 React/Python 하드코딩을 줄였습니다.

개선

운영 image 재현성

기본 Compose에서 source mount를 제거해 host checkout이 image를 암묵적으로 바꾸는 문제를 줄였습니다.

비용

action chunk의 container hop

작은 수치 배열이 Worker에서 Cyclo로 이동합니다. image 중계보다 부담은 작지만 latency 측정은 필요합니다.

비용

protocol 호환성 관리

EngineCommand 변경 시 Cyclo와 Worker version 조합을 함께 관리해야 합니다.

보완
Sensor readiness
LeRobot load가 wait_for_ready() 실패를 무시해 일시적으로 joint가 없는데도 성공할 수 있습니다. 모든 config camera를 기다려 policy가 쓰지 않는 cam_right_head도 경고합니다.
보완
Worker status timeout
모델 작업 중 DESCRIBE 조회가 2초 timeout으로 보일 수 있습니다. action timeout과 별개지만 status 경로를 비차단 또는 cache 기반으로 다듬어야 합니다.
검증
ARM64와 실제 GR00T
실제 checkpoint LOAD, observation, action chunk와 fault를 target robot에서 확인해야 완료입니다.
